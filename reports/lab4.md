# Lab4：文件系统与 I/O

## 一、功能总结

本实验为 easy-fs 增加持久化硬链接计数、目录项复用和 inode/数据块回收；实现 `linkat`、`unlinkat`、`fstat`，并保留前面章节的时间、内存映射、进程创建与调度功能。文件系统支持多个文件名共享同一 inode，只有最后一个链接删除时才释放存储资源。

## 二、设计说明

- 在 `DiskInode` 中记录 `nlink`，新建 inode 时初始化为 1。
- 创建硬链接时，在根目录加入指向同一 inode 的新目录项并增加 `nlink`。
- 删除链接时将目录项置为空并供后续创建复用，避免根目录反复缩放造成数据块泄漏。
- 当 `nlink` 降为 0 时，释放文件的直接块、一级/二级间接块及 inode 位图项。
- `fstat` 通过文件描述符取得 inode 编号、类型和链接数，并按字节写回用户缓冲区，支持结构体跨页。

## 三、问答题

### easy-fs 中 root inode 起什么作用？如果其内容损坏会怎样？

root inode 是整个文件系统命名空间的入口。它本身是一个目录文件，内容由一组目录项组成；每个目录项把文件名映射到 inode 编号。内核挂载 easy-fs 后，文件的查找、创建、硬链接和删除都从 root inode 开始，因此它既负责定位普通文件，也维持这些文件的可达性。

如果 root inode 的目录内容损坏，文件名可能指向错误 inode、非法 inode 或彼此重叠，导致文件无法找到、读到错误数据，甚至在删除时错误回收仍被使用的数据块。即使普通文件的数据块仍完好，只要对应目录项丢失，它们也会成为不可达的孤立数据。若 root inode 自身的块索引或大小字段损坏，遍历目录还可能越界访问块设备或触发内核断言。因此真实文件系统通常需要一致性检查、日志或写时复制等机制来保护和恢复目录元数据。
